## 📌 Challenge Overview

We are given:

* `encryptor.py`
* `ciphertext.json`

The challenge internally uses the format name `nonce-vault-v1`, while the challenge itself is titled **SwitchYard**.

The encryption script:

1. Generates classic DSA domain parameters `(P, Q, G)` with a **1024-bit `P`** and **160-bit `Q`**.
2. Generates a random private key `x` and computes:

```text
public = G^x mod P
```

3. Signs 14 fixed messages:

```text
dispatch/00/receipt
...
dispatch/13/receipt
```

4. For every DSA signature, the challenge leaks the **top 32 bits** of the per-signature nonce `k`.
5. A symmetric key is derived from the private key using SHA-256 and stretched using SHAKE-256.
6. The flag is XOR-encrypted and authenticated using HMAC-SHA256.

The goal is therefore:

> **Recover the DSA private key `x` from the signatures and leaked nonce bits, then decrypt the flag.**

# 🔓 Vulnerability

## DSA Signing

The standard DSA signing equations are:

```text
z = H(m) mod q

r = (g^k mod p) mod q

s = k^-1 (z + xr) mod q
```

Rearranging the signing equation gives:

```text
k ≡ s^-1 (z + rx) mod q
```

The vulnerability is that the challenge leaks the **upper 32 bits** of every nonce `k`.

This allows us to write:

```text
k_i = counter_i · 2^128 + a_i
```

where:

* `counter_i` = leaked high 32 bits
* `a_i` = unknown lower 128 bits
* `0 ≤ a_i < 2^128`

Since `Q` is 160 bits, each nonce consists of:

```text
32 known bits + 128 unknown bits
```

With 14 independent signatures, this becomes enough information for a **Hidden Number Problem (HNP)** lattice attack.

---

# 🧮 Setting Up the Hidden Number Problem

From:

```text
k_i ≡ s_i^-1 (z_i + r_i x) mod q
```

and:

```text
k_i = counter_i · 2^128 + a_i
```

we get:

```text
a_i ≡ (s_i^-1 z_i - counter_i · 2^128)
      + (s_i^-1 r_i)x (mod q)
```

Define:

```text
t_i = s_i^-1 r_i mod q

u_i = s_i^-1 z_i - counter_i · 2^128 mod q
```

Therefore:

```text
a_i ≡ u_i + t_i x (mod q)
```

or:

```text
a_i - t_i x ≡ u_i (mod q)
```

The important point is that:

* `t_i` is known
* `u_i` is known
* `a_i` is small
* `x` is the same unknown private key across all signatures

So we have **14 linear congruences with small unknown errors**, which is exactly the structure needed for an HNP lattice attack.

# 🧱 Lattice Construction

We construct the lattice generated by:

```text
q · e_i
```

for each `i`, together with:

```text
t = (t_1, t_2, ..., t_14)
```

This gives a rank-14 lattice.

The generator matrix is initially:

```text
M0 =
[q  0  0  ...  0]
[0  q  0  ...  0]
[0  0  q  ...  0]
[.  .  .       .]
[0  0  0  ...  q]
[t1 t2 t3 ... t14]
```

We apply LLL reduction to obtain a proper 14-vector basis.

```python
M0 = IntegerMatrix(n + 1, n)

for i in range(n):
    M0[i, i] = Q

for j in range(n):
    M0[n, j] = ts[j]

LLL.reduction(M0)
```

Then we extract the non-zero rows as our lattice basis:

```python
B = [
    [M0[i, j] for j in range(n)]
    for i in range(n + 1)
    if any(M0[i, j] != 0 for j in range(n))
]

assert len(B) == n
```

# 🎯 CVP → SVP Using Kannan Embedding

We know:

```text
a - u ∈ L
```

where:

```text
a = (a_1, ..., a_14)
u = (u_1, ..., u_14)
```

Because every `a_i` is smaller than `2^128`, recovering `a` can be viewed as a **Closest Vector Problem (CVP)**.

We transform this CVP into an SVP using **Kannan's embedding**.

The embedding matrix is:

```text
[ B   0 ]
[ -u  K ]
```

where:

```text
K = 2^128
```

This weight matches the bound of the unknown nonce portions.

In the reduced lattice, we expect to find a short vector of the form:

```text
(-a_1, -a_2, ..., -a_14, K)
```

The solve script performs:

```python
K = 1 << BOTTOM_BITS

M1 = IntegerMatrix(n + 1, n + 1)

for i in range(n):
    for j in range(n):
        M1[i, j] = B[i][j]

for j in range(n):
    val = us[j] if us[j] <= Q // 2 else us[j] - Q
    M1[n, j] = -val

M1[n, n] = K

LLL.reduction(M1)
BKZ.reduction(M1, BKZ.Param(block_size=20))
```

Then we locate the row whose final coordinate is exactly `K`:

```python
row = next(
    r for r in range(n + 1)
    if M1[r, n] == K
)
```

Recover the unknown low bits:

```python
a = [-M1[row, j] for j in range(n)]

assert all(
    0 <= v < (1 << BOTTOM_BITS)
    for v in a
)
```

# 🔑 Recovering the Private Key

Once all `a_i` values are known:

```text
k_i = counter_i · 2^128 + a_i
```

In Python:

```python
ks = [
    (counters[i] << BOTTOM_BITS) + a[i]
    for i in range(n)
]
```

From the original DSA equation:

```text
s = k^-1(z + xr) mod q
```

we can recover:

```text
x = (sk - z)r^-1 mod q
```

Implementation:

```python
zs = [
    int.from_bytes(
        hashlib.sha256(msgs[i]).digest(),
        'big'
    ) % Q
    for i in range(n)
]

xs = [
    (
        (ss[i] * ks[i] - zs[i])
        * pow(rs[i], -1, Q)
    ) % Q
    for i in range(n)
]
```

All 14 signatures independently produce the same private key.

The recovered value is:

```text
x = 593905689006170122564385200750061817517983039790
```

We can verify it using the public key:

```python
x = max(set(xs), key=xs.count)

assert pow(G, x, P) == int(data['public'], 16)
```

Result:

```text
public key match: True
```

# 🔐 Decrypting the Flag

The encryption script derives the symmetric key as:

```python
DOMAIN = b"BCSCTF-2026/nonce-vault/v1"

key = hashlib.sha256(
    DOMAIN + x.to_bytes(20, "big")
).digest()
```

The challenge also provides:

* `salt`
* `sealed`
* `tag`

First, verify the HMAC:

```python
salt = bytes.fromhex(data['salt'])
sealed = bytes.fromhex(data['sealed'])

assert hmac.new(
    key,
    salt + sealed,
    hashlib.sha256
).digest() == bytes.fromhex(data['tag'])
```

Then regenerate the XOR keystream:

```python
pad = hashlib.shake_256(
    key + salt
).digest(len(sealed))
```

Finally:

```python
flag = bytes(
    a ^ b
    for a, b in zip(sealed, pad)
)

print(flag.decode())
```

The HMAC check succeeds:

```text
HMAC tag match: True
```

And the recovered flag is:

```text
bcsctf{h1gh_b1t5_0f_n0nc35_5h4773r_pr1vate_k3y5}
```

# 🧠 Takeaway

The critical mistake was leaking bits of the DSA nonce `k`.

Even though only the **top 32 bits** were exposed, collecting enough signatures allowed the remaining unknown portions to be modeled as small values in a Hidden Number Problem.

A lattice reduction attack using:

* **LLL**
* **BKZ**
* **Kannan embedding**

was then sufficient to recover the complete nonce values and ultimately the DSA private key.

The general lesson is:

> **Never leak any bits of a DSA/ECDSA nonce.**

Nonce information must remain secret and unpredictable. Even partial leakage across multiple signatures can be enough to recover the private key.
